# tdd-guard — механический TDD-гейт

[tdd-guard](https://github.com/nizos/tdd-guard) — это не скилл и не текстовое
правило, а **хук Claude Code**, который физически блокирует запись кода, пока нет
падающего теста. Проще говоря: нельзя написать реализацию вперёд, а потом
«подогнать» под неё тест — хук перехватывает каждый `Write`/`Edit` и спрашивает у
модели «есть ли красный тест, который это оправдывает?». Нет — правка отклоняется.

Зачем: текстовые TDD-правила не держатся под давлением — LLM проскакивает их и
пишет имплементацию первой. Хук работает на уровне инструмента, обойти его
«забывчивостью» нельзя.

## Что он блокирует

- **Имплементация без красного теста** — новая функция/логика, под которую нет
  упавшего теста.
- **Over-implementation** — кода больше, чем нужно для прохождения текущего
  падающего теста (лишние ветки, методы про запас).
- **Несколько тестов разом** — добавление более одного теста за раз (TDD =
  один красный тест за цикл). Ровно один новый тест разрешён.

Чисто-рефакторные правки и правки тестов проходят. Если гейт мешает законному
рефакторингу — выключите его на время (см. ниже).

## Как это собрано в этом репо

| Файл                    | Роль                                                                                                                                      |
| ----------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| `package.json`          | devDeps `tdd-guard` (хук) + `tdd-guard-jest` (репортёр)                                                                                   |
| `jest.config.mjs`       | `reporters: ['default', 'tdd-guard-jest']` — пишет результаты тестов в `.claude/tdd-guard/data/`, оттуда хук узнаёт, есть ли красный тест |
| `.claude/settings.json` | два хука: `PreToolUse` (сам гейт) + `UserPromptSubmit` (ловит команды on/off)                                                             |
| `.gitignore`            | `.claude/tdd-guard/` — рантайм-данные не коммитим                                                                                         |

Хук-команда: `VALIDATION_CLIENT=cli USE_SYSTEM_CLAUDE=true npx tdd-guard`.

- `cli` + `USE_SYSTEM_CLAUDE=true` → валидация идёт через системный `claude` (вашу
  подписку Claude Code), **API-ключ не нужен**. Дефолтный `sdk`-клиент в нашем
  trial возвращал прозу вместо JSON и падал — поэтому зафиксирован `cli`.
- `npx` нужен потому, что пакет стоит локально (devDep), а не глобально — голый
  `tdd-guard` из официального README не нашёлся бы в PATH сессии.

## Как пользоваться

Ничего делать не надо — хук активен в любой сессии Claude Code, открытой в корне
репозитория. Пишете реализацию без падающего теста → правка отклоняется с
объяснением и подсказкой «сначала напиши тест».

**Выключить** (на рефакторинг, на отладку, когда гейт мешает):

```
tdd-guard off
```

Просто напишите это сообщением в сессию. Состояние пишется в
`.claude/tdd-guard/data/config.json` (`{"guardEnabled":false}`).

**Включить обратно:**

```
tdd-guard on
```

## Цена

Каждая правка нетестового файла при включённом гейте = один вызов модели
(`claude`), ~15 секунд паузы и расход токенов подписки. Это плата за гейт.
Выключенный гейт не вызывает модель вообще (срабатывает мгновенно). Тестовые
файлы и рефакторинг модель не дёргают.

- ✅ Имплементация без красного теста → **заблокирована** («Premature

- ✅ Та же имплементация при наличии падающего теста → **разрешена** («Green

- ✅ `tdd-guard off` снимает блок мгновенно; `tdd-guard on` возвращает.
- ✅ `npm test` (выборка) проходит как раньше — репортёр только дописывает JSON
  после прогона, на результаты тестов не влияет.
