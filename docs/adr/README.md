# Architecture Decision Records (ADR)

Здесь живут **архитектурные решения** проекта — по одному файлу на решение.

Зачем: чтобы «почему мы так сделали» не терялось в переписке и git-логе.
Когда субагент или новый участник спрашивает «почему RAG на SQLite, а не на
Vertex?» — ответ здесь, а не в чьей-то голове.

## Когда заводить ADR

Заводи новый ADR, когда принято решение, которое:

- меняет архитектуру (новый провайдер, новая БД, смена движка);
- трудно/дорого откатить;
- кто-то через полгода спросит «почему так, а не иначе».

Мелкие решения (имя переменной, формат строки) — НЕ ADR. Доменные термины —
в [`../../CONTEXT.md`](../../CONTEXT.md).

## Формат

Имя файла: `NNNN-короткий-заголовок.md` (порядковый номер, kebab-case).
Структура — пять разделов:

```markdown
# ADR-NNNN: Заголовок

## Status

Proposed | Accepted | Superseded by ADR-XXXX | Deprecated

## Context

Что за ситуация, какие были варианты, какие ограничения.

## Decision

Что решили. Конкретно.

## Consequences

Что из этого следует — и хорошее, и плохое (trade-offs, что теперь нельзя).
```
