# Test-Suite Honesty & Coverage Audit — quantika-demo

_Read-only audit · 2026-05-28 · branch `dw/test-coverage-2026-05-28`_

**Scope:** 813 test files (~117K LOC), Jest. Audited in 30 domain chunks by parallel auditors; every fake-confidence and coverage-gap claim was then re-checked by an adversarial verifier. 32 claims were refuted on verification and dropped.

## Executive summary

Across ~813 test files the suite is **broad but dishonest in its most security- and money-critical corners**. Verified against source: many "regression locks" do not exercise the SUT at all — they re-implement production logic locally (`confidence-guard.test.ts` redefines `VALID_CONF` inline; `email-confidence-tier.test.ts` redefines the tier function; match-freshness/effectiveScore/isComputing tests mirror `MatchesClient.tsx`/`page.tsx`), mock the very thing they claim to protect (`gamma-18-F10` mocks `requireSession` so it can never detect the auth call being deleted from the route), or assert tautologies (`expect(true).toBe(true)`, `events.length >= 0`, `status` in `[200,400]`, hardcoded-constant-vs-hardcoded-constant version checks). A second systemic rot is **source-text grep masquerading as behavioral tests** (`fs.readFileSync` + `toContain` across ~15 component/page files) and **bug-pinning tests** that lock broken behavior as the contract (H1 truncation `=== 2050`, RC5 inverted 429-retry assertion) so a correct fix reads as a regression. Genuinely strong areas exist — SQLite-backed migration tests, ai-provider routing/cost math, repository CRUD, RRF merge, governance state machines — but they sit next to critical gaps where the real implementation is never run. The headline danger: **the SQL-injection, admin-auth, ROI-auth, and money-calculation guards either have no direct test or have tests that pass identically whether the guard exists or not.**

**Totals (post-verification):** 195 findings — 87 fake-confidence, 26 over-mocked, 14 stale/skipped, 45 critical untested paths, 23 flaky. 0 uncertain. 32 refuted & dropped.

## Top 10 most dangerous

1. **`__tests__/regression/RC6-security-blacklist/spec15-CRIT01-sql-injection-tablename.test.ts:52-57 (and CRIT02 ftstable:52-58)`** _(FAKE_CONFIDENCE, critical)_ — The first SQLi case uses bare .rejects.toThrow() — it passes on BOTH buggy and fixed code because the injection itself crashes SQLite. The allowlist guard in pipeline.ts:86-88 is the only thing standing between user-controlled tableName and raw SQL; its primary regression lock cannot detect the guard's removal.
2. **`tests/regression/RC6-security-blacklist/gamma-18-F10-missing-auth-check.test.ts:24-33`** _(OVER_MOCKED, critical)_ — The sole auth regression lock for /api/analytics/roi mocks requireSession itself, so the mock returns 401 even if the route stops calling requireSession entirely. Deleting the real auth check from the handler leaves this test green — a public-data-leak regression would ship undetected.
3. **`lib/auth/admin.ts (requireAdmin) — no direct unit test; mocked in all consumers`** _(COVERAGE_GAP, critical)_ — requireAdmin is the single auth gate for every /api/admin/* endpoint (500 on missing ADMIN_TOKEN, 401 on bad/missing header, null on valid). All three branches are only ever mocked; a logic inversion or comparison bug in the real gate has zero test that would fail.
4. **`lib/laytime/calculator.ts:101,125 — portHolidays + weatherDelayHours untested`** _(COVERAGE_GAP, high)_ — These two branches directly subtract from used laytime and therefore swing demurrage/despatch money. No test passes holidays or a non-zero weather delay, so a sign error or off-by-one in charterparty D/D money calc is invisible. Verified: both code paths exist and mutate usedLaytimeHours.
5. **`lib/economics/__tests__/index.test.ts:5-41 + __tests__/api/economics.test.ts:74-91 (computeEconomics fully mocked; fueleu only in RC-fueleu-flag)`** _(OVER_MOCKED, high)_ — computeEconomics is the money-aggregation orchestrator; all four sub-modules and the route call are mocked, so the cost-summation loop and totalUsd assembly (the actual figures brokers quote) are never executed. calculateFuelEu (EU regulatory penalty math) is mocked everywhere and never unit-tested for its computation.
6. **`lib/whatsapp/scheduler.ts:98-129 — sendMorningDigests has zero coverage`** _(COVERAGE_GAP, high)_ — Verified: real production cron entry point that queries whatsapp_users, sends texts, and writes last_digest_sent_at. Only the pure predicate shouldSendDigestNow is tested. A bug in the DB query, the sent/skipped counters, or the timestamp update would silently double-send or skip every user's digest.
7. **`middleware.ts:104-145 — rate-limit (429) and CSRF (403) on /api/ai/* and /api/emails/* untested`** _(COVERAGE_GAP, high)_ — Two security gates (aiRateLimiter.check → 429, checkCsrfRequest → 403) for authenticated AI/email routes have no middleware-level test. Regressions here either open the LLM cost surface to abuse (429 removed) or disable CSRF on state-changing routes (403 removed) with no failing test.
8. **`lib/deadlines/subs-guardian.ts:111-117 (dispatcher resilience) + components/deadlines/SubsCountdown.tsx:86 (CTA branch)`** _(COVERAGE_GAP, high)_ — Verified: the per-channel try/catch ensures one failing notification channel does not drop the rest — no test injects a throwing dispatcher, so a regression that lets one failure abort all deadline notifications is uncaught. The SubsCountdown '2h'/'expired' escalation CTA (the action users actually click near deal expiry) is also untested.
9. **`lib/ai-provider.ts — signal propagation, thinkingBudget forwarding, and claude-cli routing path all untested`** _(COVERAGE_GAP, high)_ — AbortSignal forwarding (lines 455/471) gates the 85s timeout invariant; a dropped signal hangs every LLM endpoint forever. thinkingBudget (2-3x cost) and the claude-cli switch-case in callAiJson/callAiText (incl. extractJson wrapping) have no test, so cost-blowup and routing regressions are silent.
10. **`__tests__/components/confidence-guard.test.ts:11 + __tests__/components/email-confidence-tier.test.ts:4-8 (+ inline mirrors in matches-*/sample-demo-match/deterministic-sweep)`** _(FAKE_CONFIDENCE, critical)_ — Verified: VALID_CONF is redefined as a local Set with no SUT import; getEmailConfidenceTier is re-implemented in the test. The same anti-pattern recurs across match-freshness, effectiveScore, sample-demo-match guard, and the deterministic-sweep copy. Deleting the real production files leaves every assertion green — these tests measure nothing about shipped code.

## Which critical subsystems lack real coverage

**Auth — NO real coverage at the gate.** The two cornerstone gates are tested in name only: `lib/auth/admin.ts:requireAdmin` (verified to encode 500/401/null logic) is mocked in every consumer and never unit-tested; the ROI auth regression lock (`gamma-18-F10`) mocks `requireSession` so removing the real call still returns 401. Middleware rate-limit/CSRF for `/api/ai/*` (`middleware.ts:104-145`) is untested. Lower primitives (cookie signing, CSRF token gen) are genuinely covered, but the gates that actually decide access are not. **Verdict: NOT covered where it counts.**

**Parsers — partial real coverage, hollow at the edges.** `parseCargoAIResponse`/`parseVesselAIResponse`/`parseRecapAIResponse` have genuine edge-case tests. But the schema and prompt tests inspect static config objects/string constants (`parse-cargo.test.ts`, `judge-parse-vessel.test.ts`) — they pass even if the parser is deleted. The flag-judge `judgePair()` is only in a fully-skipped describe with empty bodies. The recap route's 504-timeout, <5-email threshold, and 403-CSRF branches are untested. **Verdict: core extraction covered; integration and guard paths NOT.**

**Migrations — genuinely the strongest subsystem.** Tests run real SQL against in-memory SQLite with FK enforcement, consistently covering up/down/idempotency/constraints. Gaps are narrow but real: migration 025 (fx_rates) and 040 (counter_offers) are exercised only via repos that inline their own DDL, so the actual migration SQL never runs; migration 034's silent row-deleting dedup step has no isolation test. **Verdict: REAL coverage, with two specific blind spots in the newest/most-mutating migrations.**

**Money/Cost math — alarmingly mocked or absent.** `computeEconomics` is tested with all four sub-modules mocked (`index.test.ts:5-41`), so the summation loop producing quoted figures never runs. The route test asserts a value defined in its own mock (`economics.test.ts:74-91`). `calculateFuelEu` (EU penalty math) is mocked everywhere and never directly unit-tested. The TCE regression "lock" compares two identical calls (idempotency, not correctness). The laytime calculator's holiday/weather money branches (verified at `calculator.ts:101,125`) are uncovered. Canal `quoteKiel`/`quoteBosporus` error paths untested. **Verdict: NOT covered — the numbers brokers act on are unverified end-to-end.**

**LLM error handling — mixed; the throw paths are dark.** Real strengths: Bedrock CoT-preamble extraction, computeCostUsd, LLMTimeoutError→504 handling on some routes, audit logging — all with real SQLite. But AbortSignal propagation, `thinkingBudget` forwarding, and the `claude-cli` routing path through callAiJson/callAiText have zero tests; the Gemini no-schema `extractJson` fallback is asserted only on SDK config, not behavior. Voice-transcribe re-throws non-timeout errors with no test; llm-enrich has no callAiJson-throws test. **Verdict: happy/timeout paths covered; signal/cost/non-timeout-error paths NOT.**

**Single biggest risk:** the security-critical guards (SQL-injection allowlist, admin-token, ROI/session auth) are protected by tests that pass identically whether the guard exists or not — mocked SUTs, locally re-implemented logic, and bare `.toThrow()` that catches the wrong exception. The suite will stay green through the exact regressions it was written to prevent, giving false assurance on the highest-blast-radius code in the product.
