# Mobile UX Audit — 2026-05-22

**Branch:** `audit/mobile-ux`  
**Viewports tested:** 375px (iPhone SE/14) and 390px (iPhone 15 Pro)  
**Method:** Playwright headless + static code analysis  
**Screens covered:** `/` · `/dashboard` · `/matches` · `/match/[id]` · `/processing` · `/upgrade` · `/more`

---

## Context: Production Build Gap

The running production server (`pm2: quantika-demo`) was last built on **2026-05-18**. Three features merged after that build are not yet deployed:

| Feature | Merged | Impact |
|---|---|---|
| BottomNav + body clearance CSS | 2026-05-19 (PR #275) | No mobile nav; body has 0px padding-bottom |
| `/more` page | 2026-05-20 (PR #295) | 404 in production |
| BottomNav Market link | 2026-05-22 (PR #345) | n/a (BottomNav not built) |

Findings marked **(code-only)** were measured against the source; findings without that tag were confirmed by Playwright on the production URL.

## Findings

### CRITICAL

#### C-1 — Production `/more` returns 404 · `app/more/page.tsx`
**Confirmed by Playwright.** `/more` is linked from BottomNav (`href="/more"`) but the production build doesn't include the page (added after May 18 build). Mobile users tapping "More" in BottomNav hit a 404. This includes the only way to log out on mobile.

**Fix:** Rebuild and deploy. `npm run build && pm2 restart quantika-demo --update-env`.

---

### HIGH

#### H-1 — BottomNav missing from production build · `components/nav/BottomNav.tsx`, `app/layout.tsx`
**(code-only — not yet deployed)** BottomNav is in `app/layout.tsx` line 48 but the build predates PR #275. Production body has 0px padding-bottom (confirmed Playwright), meaning content extends to the raw device bottom when the nav IS deployed — the clearance CSS also ships with PR #275.

**Fix:** Same as C-1 — rebuild. After rebuild, the `@media (max-width: 767px) { body { padding-bottom: calc(56px + env(safe-area-inset-bottom, 0px)) } }` rule in `app/globals.css` will activate.

---

#### H-2 — `/matches`: 8 touch targets below 44px · `app/matches/MatchesClient.tsx`
**Confirmed by Playwright** at both 375px and 390px.

| Element | Measured | Expected |
|---|---|---|
| Status chips (All / shortlist / saved / dismissed / archived) | 30px tall | 44px |
| "Advanced Filters" chip | 30px | 44px |
| Match action buttons (Save / Dismiss / Archive) | 24px | 44px |

Status chips use `px-3 py-1 text-sm` (30px). Action buttons use `px-3 py-1 text-xs` (24px).  
**Fix:** Change `py-1` → `py-2.5` on chips (line ~203–223) and `py-1` → `py-3` on action buttons (line ~500–530).

---

#### H-3 — Bulk action footer will overlap BottomNav · `app/matches/MatchesClient.tsx` line 542
**(code-only)** When matches are selected, the bulk footer is `fixed bottom-0 z-50`; BottomNav is `fixed bottom-0 z-30`. After the build is updated, the footer will cover the nav. The footer has no `padding-bottom` to clear the safe area or BottomNav.

**Fix:** Add `pb-[calc(56px+env(safe-area-inset-bottom,0px))]` to the bulk footer `div` (line 542). Also, bulk action buttons are `py-1.5` (~32px tall) — increase to `py-3`.

---

#### H-4 — `/upgrade` not discoverable from mobile navigation · `components/nav/BottomNav.tsx`, `app/more/page.tsx`
**(code-only)** Neither BottomNav (tabs: Home / Matches / Market / More) nor `/more` (only logout) links to `/upgrade`. Mobile users have no path to the paid plan conversion screen.

**Fix options (pick one or both):**
- Add "Upgrade" entry to `/more` page: `<Link href="/upgrade">Upgrade to Pro</Link>` 
- Or replace the "Market" tab in BottomNav with "Upgrade" (more prominent but loses market access from nav)

---

#### H-5 — `/more` page has only a logout button · `app/more/page.tsx`
**(code-only — page is 404 in production)** The page renders one action. Standard mobile pattern: "More" is the secondary navigation hub for all flows that don't fit the primary 3–4 tabs.

**Fix:** Add at minimum: `/upgrade` link, help/support contact link. Optionally: profile settings, about, legal/privacy.

---

### MED

#### M-1 — Dashboard: 2 touch targets below 44px · `app/dashboard/page.tsx`
**Confirmed by Playwright.**

| Element | Measured |
|---|---|
| `a[Review →]` (PriorityCard links) | 16px tall |
| `a[View Summary & Impact →]` | 36px tall |

PriorityCard links: likely `text-sm` inline anchors without vertical padding.  
**Fix:** Add `min-h-[44px] inline-flex items-center` or `py-2.5` to both link variants.

---

#### M-2 — Match detail: 6 touch targets below 44px · `app/match/[id]/page.tsx`
**Confirmed by Playwright.**

| Element | Measured |
|---|---|
| `a[Back to Dashboard]` | 20px |
| `button[💡 Explain this deal]` | 28px |
| Tab buttons (Vessels / Economics / Passport) | 38px |

**Fix:**
- Back link (line ~52): add `py-2` → gives 44px+. Or wrap with `min-h-[44px] flex items-center`.
- Explain button: `py-1` → `py-2.5`.
- Tab buttons: already close at 38px, add `py-2.5` to reach 44px.

---

#### M-3 — "Back to Dashboard" link: text-only, 20px tall · `app/match/[id]/page.tsx` line ~52
**Confirmed by Playwright** (`351x20px` at 375px; `366x20px` at 390px). Duplicate of M-2 — highlighted because the back-nav pattern is high-frequency on mobile.

```tsx
// Current — only text height
<Link href="/dashboard" className="flex items-center gap-1 text-sm text-muted-foreground">

// Fix
<Link href="/dashboard" className="flex items-center gap-1 text-sm text-muted-foreground min-h-[44px]">
```

---

#### M-4 — Processing page: "Try again" button is 16px · `app/processing/page.tsx` line ~239
**Confirmed by Playwright** (`54x16px`). The error recovery action is a `text-xs underline hover:no-underline` inline text link — not a button-shaped target.

```tsx
// Current
<button className="mt-2 text-xs underline hover:no-underline">Try again</button>

// Fix
<button className="mt-2 px-4 py-2.5 text-xs rounded bg-destructive/10 border border-destructive/30 min-h-[44px]">Try again</button>
```

---

#### M-5 — "More" tab never shows active state · `components/nav/BottomNav.tsx` line 72–74
**(code-only)** `aria-current={undefined}` is hardcoded on the "More" link — it never reflects active state even when the user is on `/more`.

```tsx
// Current (line 72–74)
<Link href="/more" aria-current={undefined} className="... text-muted-foreground">

// Fix: add isMoreActive helper and conditional styling
function isMoreActive(pathname: string): boolean {
  return pathname === '/more';
}
// Then apply the same active-state pattern as the other tabs
```

---

#### M-6 — No BottomNav active state on `/upgrade` · `components/nav/BottomNav.tsx`
**(code-only)** None of `isHomeActive`, `isMatchesActive`, `isMarketActive` cover `/upgrade`. All four tabs appear inactive when viewing the upgrade page.

**Fix:** Map `/upgrade` under an existing active check (e.g., add `pathname === '/upgrade'` to `isMoreActive` once it exists).

---

#### M-7 — Processing page spinner off-center on mobile · `app/processing/page.tsx`, `app/globals.css`
**(code-only)** The page uses `flex min-h-screen justify-center` but `globals.css` adds `padding-bottom: calc(56px + safe-area)` to the body on mobile. The spinner center is visually shifted upward by ~28px.

**Fix:** Add `pb-14` to `<main>` in the processing page to compensate:
```tsx
<main className="flex min-h-screen flex-col items-center justify-center px-6 bg-white pb-14">
```

### LOW

#### L-1 — Mixed Russian/English in dashboard empty state · `app/dashboard/page.tsx` line 57
Button label "Загрузить письма" in an otherwise all-English UI.

```tsx
// Fix: standardize to English
<Link href="/processing" ...>Upload emails</Link>
```

---

#### L-2 — `/upgrade` uses Tailwind hardcoded colors · `app/upgrade/page.tsx`
`bg-gray-50`, `text-gray-900`, `text-gray-500`, `text-gray-600` instead of CSS variable tokens (`bg-background`, `text-foreground`, `text-muted-foreground`). Inconsistent with the rest of the app; will break dark mode if added.

**Fix:** Replace hardcoded Tailwind gray classes with design token classes across `app/upgrade/page.tsx` and `components/upgrade/UpgradeTierCard.tsx`.

---

#### L-3 — `/more` height uses `calc(100vh-56px)` without safe-area · `app/more/page.tsx` line 9
```tsx
<div className="flex min-h-[calc(100vh-56px)] ...">
```
Hardcodes the BottomNav height without safe-area inset. On notched devices (iPhone X+), the visible area will be slightly off.

**Fix:**
```tsx
<div className="flex min-h-[calc(100vh-56px-env(safe-area-inset-bottom,0px))] ...">
```
Or more robustly: use `pb-safe` (if Tailwind plugin installed) or `calc(100dvh - 56px)`.
