## 2. Логика порядка (3 правила)

1. **Одна «поверхность» — одна волна.** Поверхность = группа файлов одного механизма (движок
   матчинга, экономика, парсер, UI). Два бага правят одни файлы → нельзя параллельно (конфликты
   правок). Движок — строго по очереди; UI + парсер + конфиги — параллельно (разные файлы).
2. **Дёшево и ломает демо → раньше. Тяжёлое продуктовое → в конец.** Кнопки-обманки сразу
   (дёшево, позорно на демо). «Скоринг считает деньги» / «скорость судна из писем» — большие,
   требуют обсуждения, идут последними.
3. **Перед каждым фиксом — проверка против реального кода.** Урок formatAge: аудит пометил
   «живой баг», оказался мёртвый код. Каждый баг сначала воспроизводим/грепаем на текущем main.

## 6. Дисциплина — одинакова в каждой сессии (v4.0 конвейер)

1. **Разведка** — 3 агента ищут КОРЕНЬ (не симптом), проверка против реального main.
2. **План** — отдельная сессия пишет план фикса.
3. **Исполнение + тесты (TDD)** — тест → зелёный.
4. **Risk** (парсер/auth/экономика/seed) → независимый QA `/test-skill` на реальных формах (не happy-path).
5. **Прод-data-write** → `--dry` сначала, бэкап, потом write (Rule #22).
6. **Видимое** → приёмка фаундера на проде (Gate5).
7. **value-bearing число** → `VALUE_CHECK` сверка с источником/golden-set перед DONE (v4.0).
