> ТОЛЬКО для задач, НЕ касающихся матчинга. Матчинговая дорожка (движок/парсер/экономика/

## Зачем разделение

«Одна поверхность — одна волна»: два бага, правящих одни файлы, нельзя чинить параллельно
(конфликты правок). Матчинг (движок+парсер+экономика) = последовательная дорожка + пересев
данных, идёт отдельно. Здесь — 4 поверхности в РАЗНЫХ файлах → безопасны параллельно.

## Scope

**IN (эта сессия):** UI · Сессии/Хранилище · Конфиг/Прод · Security.
**OUT (другая сессия, golden-set):** B3, B4, B5, B6, B7, B8, B10, B16, B19\* — движок/парсер/
экономика/дистанции. Не трогать их файлы (real-matches, fit-breakdown, parser, economics, tce).

## Дисциплина (v4.0 — каждая задача)

1. **recon-first** — 3 агента, КОРЕНЬ не симптом, **воспроизвести на текущем main** (особенно VERIFY-FIRST: B11b, B15 — formatAge-риск «мёртвый код»).
2. **план** (отдельная сессия) → **exec TDD** (`subagent-driven-development`).
3. **risk (auth/seed/data)** → `/test-skill` на реальных формах. B20c (auth), B17-data.
4. **data-write в прод** → `--dry` + бэкап (Rule #22). B17-data, B13-если-данные.
5. **видимое** → твоя приёмка Gate5 (`USER_CHECKLIST`). B1b, B18, B14, B11b-если-live.
6. **VALUE_CHECK** — здесь почти везде **N/A** (эти задачи НЕ производят user-visible числа; в этом и смысл «безопасно параллелить»). Исключение-watch: B11b (price-badge), B13 (market-числа) — если меняют показанное число, сверить.
