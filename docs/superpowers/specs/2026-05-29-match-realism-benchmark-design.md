# Дизайн: Исследование реалистичности матчинга (match-realism benchmark)

**Дата:** 2026-05-29
**Тип:** research-документ (не код-изменение)
**Запрос:** Фаундер сомневается, что 90 грузов × ~70 судов → ~450 матчей правдоподобно.
Нужно понять реальные условия совместимости судно↔груз, дать обоснованную оценку
«сколько матчей реалистично», и объяснить, почему текущее число завышено.

## Цель

Снять сомнение фаундера обоснованным числом. На выходе — research-документ, который:

1. Объясняет, что такое «реальный матч» в dry-bulk фрахте (наша база + интернет + здравый смысл).
2. Объясняет механику, почему движок сейчас выдаёт ~450.
3. Даёт эмпирический бенчмарк на наших реальных данных: было 450 → реалистично ~N.
4. Разбирает сегменты и edge-cases (max-вариант).
5. Сверяет результат с рыночной нормой.

**Вне scope:** правка кода движка. Если по итогам решим чинить — отдельная сессия.

## Метод

**Шаг 1 — Критерии «реального матча».** Свести жёсткие условия из
`docs/research/matching-factors-2026-04/` + освежить из интернета рыночную норму
(размер tonnage list на груз, доля пар «стоит звонить», fixture conversion).

**Шаг 2 — Расчёт на наших данных.** ~80 грузов × ~60 судов из `lib/sample-data/`.
Переиспользовать нашу математику (`calculateReadinessGap`, `runHardFilters`,
`date-parsing`) и применить реальные пороги **как жёсткие отсечки**, не мягкие штрафы:

- **Даты:** open date судна укладывается в laycan ± разумное окно (с учётом перехода).
- **Балласт:** порожний переход ≤ порог по классу судна.
- **Соразмерность:** груз ≥ ~50% DWCC (иначе диспропорция).
- **Бассейн:** позиция судна и порт погрузки в совместимых морях.
  Результат — воронка с числами: ~4 800 пар → физически возможные → +даты → +балласт
  → +соразмерность → реалистичное N (с разбивкой good / на заметку).
  Пороги взять из индустрии и показать **чувствительность** (как меняется N).

**Шаг 3 — Сегменты и edge-cases.** dry bulk vs tanker/container; part-cargo
(делимость груза _добавляет_ пары); сезонность (муссон/лёд); spot vs dated.

**Шаг 4 — Сверка с реальностью.** Сравнить наше N с рыночной нормой из интернета.

## Структура отчёта (deliverable)

`docs/research/match-realism-2026-05/`:

1. Резюме для фаундера (1 стр., по-человечески).
2. Что такое реальный матч — условия + источники.
3. Почему сейчас 450 — механика (sweep + нет порога + мягкие критерии).
4. Бенчмарк на наших данных — воронка, было 450 → реально ~N, таблица отсечек.
5. Сегменты и edge-cases.
6. Сверка с индустрией.
7. Вывод + рычаги (короткий список, что чинить; без обязательства чинить сейчас).

## Допущения

- Сегмент демо — преимущественно dry bulk (handysize/supramax). Подтверждается инвентаризацией данных.
- Пороги «реальности» обосновываются из индустрии, не задаются фаундером; показывается чувствительность.
- Расчётный скрипт — research-инструмент (одноразовый), переиспользует lib-функции; не часть продакшн-движка.
