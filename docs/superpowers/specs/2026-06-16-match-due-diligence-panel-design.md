## Problem / why

Движок уже считает богатый анализ матча (fit-breakdown факторы, ветинг
суб-факторы, TCE-economics, hold-cleanliness вердикт, hard-filters осадки/кранов),
но пользователю это видно как «голый» fit% + разрозненный список факторов в правом
рейле. Нет ощущения «вау — сколько проверок Quantika реально прогнала, чтобы свести
это судно с грузом». Цель: витрина демо, которая делает невидимую работу видимой и
вызывает доверие у проспекта/инвестора.

## Goal (the "wow")

Панель **«Due Diligence»** под блоком Source Attribution на странице матча,
во всю ширину. Читается как профессиональный pre-fixture чеклист брокера:
герой-строка со счётчиком проверок + 5 сгруппированных категорий, каждая строка —
проверка с состоянием и микро-доказательством (живое число/факт).

## Decisions (locked with founder)

| Вопрос | Решение |
|---|---|
| Поверхность | Панель **в приложении**, страница матча (не в исходящем письме — отложено) |
| Подача | **Чеклист due-diligence** (не скоркарта, не проза) |
| Честность | **Все проверки в одном списке**; недоделанные — видимо неактивные (серое «не подключено / нет данных»), НЕ фейк-галка. Счётчик считает только активные |
| Построение | **Только панель на готовых данных движка** — ноль правок матч-логики |
| Название | **«Due Diligence»** |
| Локация | **Под блоком SOURCE ATTRIBUTION**, full-width |
| Существующий правый рейл факторов | В MVP не трогаем; «слить vs оставить оба» — open question, не блокирует |

## Surface & layout

- Страница матча (таб-карточка `Vessels · Economics · Passport · Quote · Emails` +
  «Explain this deal» + SOURCE ATTRIBUTION).
- Новая панель рендерится **под** SOURCE ATTRIBUTION, full-width.
- **Hero-строка** сверху: «Прогнали N проверок · X ✓ · Y ⚠ · критичных стопов нет» +
  итоговый fit% справа (берётся как есть).
- Ниже — 5 групп категорий, всё раскрыто статикой (без аккордеона в MVP).
- Узкий экран — категории стопкой (адаптив через существующую сетку).

## Check states (honesty model)

| Состояние | Иконка | Когда | Считается в счётчике? |
|---|---|---|---|
| Прошло | ✓ (ti-check, success) | проверка выполнена, ок | да |
| Флаг | ⚠ (ti-alert-triangle, warning) | caution из движка | да |
| Инфо | ℹ (ti-info-circle, info) | нейтральный факт (напр. IMSBC Group C) | да |
| Не подключено / нет данных | — (ti-minus, tertiary, курсив) | проверка не реализована ЛИБО нет данных по судну/письму | **нет** |

Правило: пустое поле (напр. `lastCargoes=null`, `ciiRating=null`) → серое «нет данных»,
НИКОГДА не зелёная галка. Совпадает с продуктовой линией «перестать врать».

## Categories & checks (MVP) — всё из существующих полей матча

Источники подтверждены аудитом (file:line — на момент HEAD `ffe47548`; plan-time
recon перепроверит точные сигнатуры).

### 1. Судно ↔ порт (физика)
| Проверка | Состояние-источник | Данные |
|---|---|---|
| DWT под объём груза (утилизация) | ✓/⚠ | фактор utilisation, `fit-breakdown.ts` |

### 2. Груз ↔ трюмы (совместимость)

Активных проверок в MVP ≈ 12-14 (демо-данные определяют точное число).

## Data flow (zero engine change)

Панель = **чистое представление**. Новый presentational-слой:
1. Принимает уже посчитанный объект матча (те же поля, что кормят правый рейл
   факторов + vetting detail 86% + economics tab).
2. Маппит каждое поле в `{ category, label, state, evidenceText }`.
3. Группирует в 5 категорий, считает hero-счётчик (только активные).
4. Рендерит компонент под Source Attribution.

Матч-логика, скоринг, бакетинг, реген — НЕ трогаются. Работает на текущем
frozen-seed (демо).

## Non-goals (YAGNI)

- Правок движка / скоринга / регена — нет.
- Новых источников данных в MVP — нет (серое остаётся серым; LOA-гейт и CII-данные =
  отдельные задачи из ROI-очереди аудита).
- Встройки в исходящее письмо — нет (отложено, возможен общий компонент позже).
- Аккордеон / сворачивание — нет (всё раскрыто).
- Drill-down модалки / PDF-экспорт / редактирование — нет.
- Замены существующего правого рейла — нет (open question на потом).

## Open questions for plan-time recon

1. Точный компонент страницы матча (где таб-карточка + SOURCE ATTRIBUTION рендерятся)
   и точная форма объекта матча, доступного UI (какие поля несут vetting-вердикты,
   hold-cleanliness, economics-breakdown, hard-filter результаты).
2. Где живут строки-доказательства (evidence) — берём из существующих
   factor-rationale строк правого рейла или собираем заново из полей?
3. Правый рейл факторов — оставить дублем или консолидировать (после MVP).
4. Демо-режим: панель читает session-копию матча или мастер? (паритет list/detail —
   см. прецеденты #856).

## Acceptance criteria

- Панель «Due Diligence» видна под SOURCE ATTRIBUTION на странице матча (прод-демо).
- Hero-строка показывает корректный счётчик активных проверок + fit%.
- 5 категорий с ✓/⚠/ℹ/серое; каждая активная строка несёт живое доказательство.
- Недоделанные проверки серые «не подключено / нет данных» — НИ ОДНОЙ фейк-галки
  (cold-QA проверяет на матче с пустыми полями).
- Ноль изменений в матч-логике (diff не трогает scoring/regen/pair-analyzer логику,
  только presentational + чтение).
- list==detail паритет не нарушен (панель — read-only представление).
