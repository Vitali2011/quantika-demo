# qa-walker v3 «разведчик» — дельта-разведка, приёмка PR, аудит логики

**Дата:** 2026-06-12 · **Статус:** spec approved (см. диалог) · **Скилл:** `~/.claude/skills/qa-walker/` (свой git-репозиторий, v2.8 → v3.0)

## Проблема

Приложение мержит ~40 PR за 3 дня (#922–964). Чеклист qa-walker — замороженный
снимок UI: каждая версия скилла (v2.1→v2.8) — ручная догонялка после волны фич.
Пример дрейфа: #960 добавил аккордеоны на match card, #963 на следующий день
убрал IMSBC-блок — скилл всё ещё описывает старый экран. У скилла нет памяти
«что я уже проверял» и нет фазы «что нового приехало с прошлого прогона».
Пер-PR верификация существует только внутри supervised-`loop` с оркестратором.

## Решения (зафиксированы с фаундером)

1. **Запуск:** дельта-прогон по требованию (не cron, не хук на деплой).
2. **Источник новизны:** PR-поток (gh) + перепись живого UI (census-дифф).
3. **Аудит логики:** отдельный режим `logic` с файлом-бэклогом проб.
4. **Архитектура:** расширение существующего qa-walker (вариант A), не новый
   скилл и не скрипт-генератор. Новые режимы переиспользуют criteria.md,
   match-economics-audit.md, auth, Chrome-MCP-дисциплину, грамматику
   `сдано/не работает`.

## Новые режимы

| Триггер             | Режим                              | Что делает                                                                                      | Бюджет    |
| ------------------- | ---------------------------------- | ----------------------------------------------------------------------------------------------- | --------- |
| `/qa-walker delta`  | дельта-разведка (основной рабочий) | merged-PR с последнего аудита → приёмочные проверки живьём + census-дифф + микро-смоук          | 30–45 мин |
| `/qa-walker pr <N>` | точечная приёмка одного PR         | deploy-проверка → деривация чеков из PR → глубокая проверка → вердикт `сдано/не работает <pr#>` | 10–15 мин |
| `/qa-walker logic`  | аудит логики движка                | 2–3 пробы из бэклога по курсору, на живых матчах прода                                          | ~30 мин   |

`full` / `auto` / `local` / `loop` — без изменений. `loop` со временем
переиспользует примитив `pr` вместо собственной копии deep-verify (рефактор,
не смена поведения).

## Память разведчика — `state/` в каталоге скилла

```
state/
  state.json    # { last_audited_sha, last_audited_pr, last_run_iso,
                #   logic_cursor, census_file }
  census.json   # перепись поверхностей прода: по каждой странице —
                # маршруты, табы, аккордеоны, CTA (вывод JS-сниппета фазы 2.8)
```

Коммитится в git скилла после каждого прогона → история «как выглядело
приложение» бесплатно. Census — генерируемые ДАННЫЕ (обновляются автоматически);
checklist.md / criteria.md — курируемые ИНСТРУКЦИИ (правки только через
writing-skills TDD). Это разделение — ответ на конфликт с Iron Law.

## Дельта-режим (сердце редизайна)

1. **Δ1 — что приехало.** Прочитать state → `rtk gh pr list --state merged`
   с `last_audited_sha`. Отсев невидимых пользователю (docs/chore/test/plan/
   recon). Для каждого видимого PR — из заголовка + body + затронутых файлов
   вывести 1–3 приёмочные проверки с конкретным маршрутом
   («#960 аккордеоны на match card → открыть /match/[id], аккордеоны
   присутствуют, данные внутри непустые и согласуются с письмом-источником»).
2. **Δ2 — проверка живьём.** Каждый чек на проде глазами брокера: дисциплина
   2.5.9 — список лжёт, открывай деталь; цифры сверяй с источником; скриншот
   на каждый fail.
3. **Δ3 — census-дифф.** Снять свежую перепись (JS фазы 2.8 по посещённым +
   nav-маршрутам), дифф со state. Поверхность появилась/исчезла и не объяснена
   ни одним PR дельты → отдельная находка (ловит реген данных, env-флаги,
   побочные эффекты соседних PR).
4. **Δ4 — микро-смоук ядра.** Фиксированный минимум: логин, топ-5 /matches
   живые (Fit ≥60, без дублей), консоль чистая, Sentry-POSTs = 0.
5. **Δ5 — отчёт + state.** Баги → issues с дедупом (как full-режим).
   `[stale-skill]`-секция: PR удалил то, что описано в checklist.md /
   criteria.md / design-system.md → точный список «что обновить в скилле»
   (сам себя скилл НЕ правит). Обновить state.json + census.json, закоммитить.

Hard Rules наследуются: never fix, скриншоты обязательны, дедуп перед filing,
буфер до финальной фазы.

## PR-режим

1. Gate-3-дисциплина из loop-mode.md: деплой подтверждён сигналом оркестратора
   (`post-deploy-checks/<pr#>/summary.json` + Pending-строка); сигнала нет →
   прямая проверка прода (build SHA), нет и её → STOP «не задеплоен».
2. Деривация приёмочных чеков из PR (как Δ1, но один PR — глубже: до 5 чеков).
3. Глубокая проверка на проде (как Δ2 + экономика, если PR трогал матчи/TCE).
4. Вердикт в грамматике оркестратора: `сдано <pr#>` / `не работает <pr#>` +
   proof (скриншот + живое значение), pre-fill через `send_message` (дефолт
   как в loop-mode).

## Logic-режим

`logic-probes.md` — бэклог проб. Формат пробы:

```markdown
### P<N>. <имя> [status: open|verified-fixed|wontfix]

- Гипотеза: <что движок делает неправильно>
- Как найти на проде: <фильтр/маршрут/паттерн матча>
- Ожидаемое / фактическое: <…>
- Severity при подтверждении: critical|high|low
- Источник: <аудит/issue/PR>
```

Сид из аудита логики 2026-06-12 (карта C): Босфор/каналы для крупнотоннажа,
durationDays=0 в TCE, IMSBC-группа A (разжижение), TCE-арифметика с override,
war-risk против актуальных JWC-зон. Прогон берёт 2–3 пробы по `logic_cursor`,
двигает курсор, результат пишет в статус пробы. Новые аудит-кампании пополняют
бэклог — знание не испаряется после сессии.

## Границы (что НЕ делаем)

- Не cron и не хук на деплой — запуск руками или оркестратором.
- Не реестр фич с налогом на каждый PR.
- Скилл не правит сам себя (кроме генерируемого `state/`) и не фиксит баги.
- full/auto/loop поведенчески не меняются в этом релизе.
- Не строим diff-парсер кода: деривация чеков из PR — суждение модели по
  заголовку/body/списку файлов, не статический анализ.

## Имплементация — через writing-skills TDD (Iron Law)

Каждый новый режим — сначала RED-бейзлайн (субагент без нового скилла получает
сценарий, фиксируем дословные провалы), потом правка, потом GREEN-прогон:

1. **RED delta:** «проверь, что нового на проде с 9 июня» — без delta-режима;
   ожидаемые провалы: агент не находит точку отсчёта, проверяет по старому
   чеклисту, пропускает #963-removal.
2. **RED pr:** «прими PR #957 на проде» — без pr-режима; ожидаемые провалы:
   верит «merged = live», неверная грамматика вердикта.
3. **RED logic:** «проверь Босфор-логику на проде» — ожидаемые провалы: нет
   методики поиска затронутых матчей, вывод не сохраняется.
4. GREEN: те же сценарии с новыми файлами; REFACTOR: закрыть найденные
   рационализации; baselines → `baselines/2026-06-1X-v3-*.md`.

Бейзлайны и правки — в git-репо скилла; спека остаётся в quantika-demo.
