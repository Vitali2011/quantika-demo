# Бенчмарк моделей через повтор PR (Variant B) — Design

**Дата:** 2026-06-13
**Цель сессии:** чистый бенчмарк моделей (цена / качество / скорость), НЕ настройка скилла.
**Вопрос, на который отвечаем:** «дороже ли = лучше», и где Opus реально окупается, а где
Sonnet-max уже на плато.

---

## 1. Что меряем и чего НЕ меряем

**Рефрейм (важно):** orchestrator-day сам задачу не делает — он диспетчер; код пишут
порождённые Sonnet-сессии. Поэтому «гонять скилл на разных моделях» размывает эффект модели
(исполнители всё равно Sonnet) и пачкает «скорость» латентностью кронов. Для **чистого**
бенчмарка модель должна тащить ВСЮ задачу сама.

**Variant B:** каждая конфигурация = один самодостаточный агент делает всю задачу на своей
модели/effort. Цена/скорость/качество чисто атрибутируются модели. Без VPS-кроновой латентности.

**Out of scope:**

- Настройка дефолтов orchestrator-day (отдельная цель — см. [[feedback_orchestrator_one_chain_rule_tested_green_2026_06_13]] про дисциплину правок скилла).
- Variant A (полный скилл end-to-end) — эффект модели размыт, отвергнут осознанно.
- Вторая задача (TCE #937) — возможный быстрый фолоу, если результаты интересны.

## 3. Конфигурации (руки) — 6 × n=3 = 18 прогонов

| #   | Рука             | Модель                                           | Effort |
| --- | ---------------- | ------------------------------------------------ | ------ |
| 1   | sonnet-max       | claude-sonnet-4-6                                | max    |
| 2   | opus-low         | claude-opus-4-8                                  | low    |
| 3   | opus-med         | claude-opus-4-8                                  | medium |
| 4   | opus-high        | claude-opus-4-8                                  | high   |
| 5   | opus-max         | claude-opus-4-8                                  | max    |
| 6   | dynamic-workflow | Workflow-скрипт, агенты на claude-sonnet-4-6/max | —      |

- **n=3** на каждую руку — против стохастического шума (как n=3 в утреннем cohesion-тесте).
- **Opus-max добавлен** к 5 исходным: без него нет head-to-head «Sonnet-max ↔ Opus-max на равном
  усилии» (иначе путаются оси модель/усилие).
- Рука 6 (workflow) пинит агентов на Sonnet-max → честный контраст «структура fan-out vs один
  сильный single-shot на той же модели».
- Опц. расширения (каждое +3 прогона): Sonnet-low/med/high (кривая Sonnet), Fable 5 (фронтир),
  Haiku (дешёвый пол).

---

## 4. Харнесс (как исполняется один прогон)

1. Свежий git worktree от `e242d259` (изоляция; сброс между прогонами).
2. Подать агенту brief (раздел 2: 3 дыры + acceptance) — БЕЗ тестов, БЕЗ reference-диффа.
3. Запуск контролируемой одиночной сессии: `claude --print --model <id> <effort-flag> < brief`
   (тот же CLI-путь, что в диспатче, но БЕЗ orchestrator-скилла и БЕЗ кронов).
4. Захват автоматом: токены (in/out), wall-clock, произведённый дифф.
5. Стоп: агент объявил done ИЛИ cap по времени (30 мин — потолок сессии).

⚠️ **Effort ставится флагом CLI, не во внутреннем Agent-вызове** → гоним через CLI-путь.
Pre-flight: подтвердить, что флаг effort жив для Sonnet и Opus.
Рука 6 — через Workflow tool (скрипт: decompose war-risk → fan-out → synthesize).

## 5. Оракул качества (3 слоя, pre-registered)

1. **Скрытые тесты (объективно, вес 50%):** после решения вкладываем тест-набор #957 в worktree
   агента и гоняем. Агент их НЕ видел → ловит подгонку. Файлы:
   `lib/economics/__tests__/war-risk.test.ts`, `…/war-risk-rates.test.ts`,
   `lib/matching/__tests__/tce-calculator-warrisk-suez.test.ts`, `__tests__/economics/war-risk.test.ts`,
   - voyage-фикстуры `tests/fixtures/voyage-tce/*.json`. Метрика = pass/total.
2. **Ловушка Суэц (объективно, вес 20%):** реализован ли `_routeTransitsSuez` (Суэц-транзит →
   `red-sea-hra` без HRA-порта) — греп + результат `tce-calculator-warrisk-suez.test.ts`.
3. **Слепой судья (вес 30%):** судья-модель (фикс, opus-high) оценивает дифф по письменному
   рубрику, НЕ зная авторства (вырезаем co-author/model-строки). Рубрик: покрыты ли 3 дыры,
   корректность, отсутствие over-scope (не трогать RAG/парсер/миграции), качество кода.

**Веса и рубрик фиксируются ДО прогонов** (анти-подгонка). Опц.: 2-й судья для устойчивости.

## 6. Метрики и модель стоимости

- **$ = in_tokens×in_price + out_tokens×out_price** по каждой модели. Прайс — из официальной
  таблицы (pre-flight заполнить; не выдумывать).
- **Скорость:** wall-clock мс (Agent/CLI отдаёт сам). Активное vs idle — отдельно, если CLI-путь
  добавляет ожидание.
- **Качество:** композит (50/20/30 из §5).
- **Переделки:** число само-коррекций внутри сессии (если наблюдаемо) — прокси решения «с первого раза».
- **Выход:** таблица по руке + главный график **«цена ↔ качество»** (frontier) + скорость.

## 7. Процедура

1. **Pre-flight:**
   - тест-набор #957 зелёный на `a8e2e3ef` (sanity оракула);
   - `2025-current.yaml` есть на старт-SHA или застейджен;
   - effort-флаг работает для Sonnet+Opus;
   - заполнен прайс-лист;
   - заморожен рубрик/веса.
2. **Пилот:** 1 рука (opus-med) n=1 → замер токенов/времени → экстраполяция сметы $ и часов на
   полные 18 → **founder go/no-go**.
3. **Полный прогон:** 18 (учёт VPS ≤3 параллельных + 30-мин cap → батчи/последовательно, либо локально).
4. **Слепая оценка** всех.
5. **Анализ:** таблица + frontier + вывод «где Opus окупается vs плато Sonnet-max».

## 8. Риски и ограничения

- **dev-LLM мёртв** → задача LLM-free (проверено: 0 провайдер-импортов); pre-flight — тесты не
  ходят в сеть.
- **VPS ≤3 параллельных + 30-мин cap** → пропускная способность; возможно локально/батчами.
- **war-risk тянет port-distances** (bundle-landmine) — это размер бандла, НЕ прогон тестов
  (тесты офлайн); подтвердить на pre-flight.
- **Effort-флаг** — feasibility на pre-flight (см. §4).
- **Стоимость** — ограничена pilot-first.
- **Bias судьи** → слепота + фикс-модель + pre-registered рубрик (+ опц. 2-й судья).
