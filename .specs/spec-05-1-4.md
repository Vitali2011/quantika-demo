## Task Description

Покрытие тестами составляет 1.4% — тестируется только `lib/currency.ts` (`lib/__tests__/currency.test.ts`). Jest и ts-jest присутствуют в devDeps (`jest@30.3.0`, `ts-jest@29.4.9`), тестовый скрипт `"jest --forceExit"` прописан в package.json, но файл конфигурации `jest.config.*` отсутствует. Без работающего тест-окружения любая правка в бизнес-логике (freshness, commission, counterparty, parsing) не имеет regression-защиты.

Задача: создать `jest.config.mjs` с preset `next/jest`, добавить `jest.setup.ts`, написать не менее 30 новых тест-кейсов, покрыв критические lib-модули (freshness, commission, counterparty, parsing utils) и маршруты AI (classify, parse-cargo).

Источники: ROADMAP item 6 «Jest setup под Next.js + первые 30 тестов»; audit-code-quality — `lib/` severity:high (нулевое покрытие всех модулей кроме currency.ts); research-tech-stack — Jest NOT_FOUND в jest.config*; gaps.md category:testing (critical); research-business-logic — freshness rules, classify logic, session signatures.

## Requirements

1. Создать `jest.config.mjs` с `createJestConfig` из `next/jest`; указать `moduleNameMapper: { "^@/(.*)$": "<rootDir>/$1" }` для поддержки path alias `@/*`; `testEnvironment: 'node'` по умолчанию (кроме тестов React-компонентов).
2. Создать `jest.setup.ts`: при необходимости добавить глобальные моки (например `global.fetch` stub для route-тестов).
3. Написать `lib/__tests__/parsing-utils.test.ts`: ≥5 кейсов для `toConfidence<T>()` (null, 0.0, 0.3, 0.7, 1.0 → 'LOW'/'MEDIUM'/'HIGH') и ≥5 кейсов для `extractNum()` (пустая строка, числовая строка, строка с пробелами, нечисловая строка, форматированное число).
4. Написать `lib/__tests__/freshness.test.ts`: ≥10 кейсов, покрыв все ветки `calculateExpiry` (VESSEL_POSITION с/без openDate, CARGO_INQUIRY с/без laycan, FIXTURE_RECAP, DOCUMENT, CLIENT_REPLY, default) и оба исхода `isStale` (просроченная дата → true, будущая → false, null → false).
5. Написать `lib/__tests__/commission.test.ts`: ≥5 кейсов для функций из `lib/commission.ts` (расчёт комиссии, edge cases нулевых значений, разные валюты).
6. Написать `lib/__tests__/counterparty.test.ts`: ≥5 кейсов для функций из `lib/counterparty.ts`.
7. Написать `app/api/ai/__tests__/classify.test.ts`: ≥5 кейсов для бизнес-логики из `classify/route.ts` — reply detection, status derivation (INFO_ONLY, RESPONDED, NEEDS_ACTION, PENDING), freshness integration; OpenAI вызовы мокировать через `jest.mock`.
8. Написать `app/api/ai/__tests__/parse-cargo.test.ts`: ≥5 кейсов для `parse-cargo/route.ts` — парсинг cargo данных, обработка AI-ответа, edge cases; OpenAI вызовы мокировать.
9. После добавления всех тестов: `npm test` должен завершаться с exit 0 и показывать ≥30 новых тест-кейсов.
