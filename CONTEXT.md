# CONTEXT — общий язык домена Quantika Demo

> Зачем этот файл. Домен фрахта/морских перевозок сложный, и одни и те же
> понятия расползаются по коду под разными именами (`tce` / `timeCharterEq` /
> `voyageRate` — всё про одно). Это и стоит токенов (агент каждый раз
> переоткрывает «что значит X»), и порождает баги naming-drift. Здесь —
> **один канонический словарь**: имена переменных, тестов, функций и
> комментариев должны совпадать с этими терминами.
>
> Правило: перед задачей читай этот файл. Новый доменный термин → добавь сюда
> в том же PR. Новое архитектурное решение → ADR в [`docs/adr/`](docs/adr/).
>
> Все ссылки на файлы проверены grep'ом на момент создания (2026-06-16).
> Если файл переехал — почини ссылку, не удаляй термин.

## Каноничные имена

term → как называть в коде. Левая колонка — **используем**, правая — **не плодим**.

| Концепт            | Каноничное имя                                                                                                                         | НЕ используем (дрейф)                                |
| ------------------ | -------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------- |
| TCE значение       | `tce_usd_per_day` (БД), `tceUsdPerDay` (объект), `TCE/day` (UI-лейбл)                                                                  | `timeCharterEq`, `voyageRate`, `dailyRate`           |
| Провайдер LLM      | `AI_PROVIDER` (глобальный env), `MATCH_PROVIDER` / `CLASSIFY_PROVIDER` / `PARSE_CARGO_PROVIDER` (scope-override), модуль `ai-provider` | произвольные новые `*_PROVIDER` без записи здесь     |
| Порт выгрузки      | `discharge_port` (БД) / `dischargePort` (camelCase)                                                                                    | `destinationPort`, `portDa`                          |
| Порт бункеровки    | `bunker_port` (БД) / `bunkerPort` (camelCase)                                                                                          | `fuelPort`, `refuelPort`                             |
| Прибыль рейса      | `voyage_pnl` / `voyagePnl`                                                                                                             | `profitLoss`, `pnl` (слишком общее)                  |
| База знаний RAG    | имена таблиц строго `imsbc_vec/fts`, `igc_vec/fts`, `jwc_vec/fts`, `bimco_vec/fts`                                                     | произвольные имена таблиц (SQLite бросит исключение) |
| Качество матча     | `matchLevel` (`good`/`possible`/`weak`) + `bucket` (UI-группа)                                                                         | смешивать `tier`/`score`/`quality` как синонимы      |
| Демо-режим         | `isDemoMode()` + env `DEMO_MODE`                                                                                                       | `isDemo`, `demoFlag`                                 |
| Дни рейса          | `voyageDays` (вход) ≠ `durationDays` (выход)                                                                                           | не путать: это разные семантики                      |
| Балластный перегон | `ballastDistanceNm`                                                                                                                    | `ballastDist`, `repositioningDistance`               |

> **Замечание про БД↔app:** системно snake_case (колонки SQLite) → camelCase (код).
> Это нормально и осознанно. Дрейф — это когда один и тот же концепт получает
> **разные корни слова** (`discharge` vs `destination`), а не разный регистр.
